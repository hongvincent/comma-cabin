# 2차 PT 시연 실행 절차 (검증한 경로)

- 목적: 2차 PT(2026-12-03~04)에서 Pleos Connect 에뮬레이터로 쉼표 캐빈을 재현 가능하게 시연한다. 스토어 출시용 절차가 아니다.
- 근거: STEP 38 최신 release 4항목 적용 뒤 자연 시간 종료·원복([verification/product-ui.md](verification/product-ui.md) 15절), STEP 36 4항목 적용·앱 이탈·원복(같은 문서 14절), STEP 35 픽업 재설정과 자연 시간 종료(같은 문서 13절), STEP 34 시트 기록 안전 STOP([verification/vehicle-controls.md](verification/vehicle-controls.md) 4-1-9), SDK 호출 분리([verification/sdk-dispatch.md](verification/sdk-dispatch.md)). STEP 18·19(0.2.0)는 지난 빌드의 기록이다(같은 문서 11·12절).
- 시트 자동 조절(F11)은 시연 요구사항에 포함되지만 현재 미충족이라 아직 시연하지 못한다([verification/seat-presets.md](verification/seat-presets.md) 6절, 공식 문의 #36).

## 2. 검증 환경

- JDK 17. Pleos Connect AVD 이미지 2.1.0(API 34, arm64). 차량 사용자는 user 10이다.
- Vehicle SDK 2.3.2, Vehicle Service 2.3.22. TextToSpeech 3.3.1(`ON_DEVICE`).
- 에뮬레이터는 `-no-snapshot -gpu host -no-audio` 설정으로 cold boot했다. `-no-audio`라 소리는 로그와 콜백으로만 확인했다.
- 기기 시계는 바꾸지 않았다. 새 계정·스토어·서버를 쓰지 않는다.

## 3. Virtual Console 연결 (필수)

- 에뮬레이터 차량 값은 Virtual Console 세션이 열려 있을 때만 바뀌었다.
  - 세션이 없을 때는 Native 공조 전원 요청이 `set value failed`로 실패했다(STEP 19).
- 준비: `adb forward tcp:8088 tcp:8088` 뒤 `http://127.0.0.1:8088`을 일반 브라우저에서 공식 가이드대로 열고, 시연 내내 그 탭을 열어 둔다.
  - 페이지는 1초마다 세션 heartbeat를 보낸다. 페이지를 닫으면 세션이 끝난다.
- 이번 자동 검증은 브라우저 화면이 아니라, 페이지와 같은 세션 heartbeat를 보내는 투명한 localhost 요청 도구로 했다. 브라우저 자동화나 권한 우회는 하지 않았다. 시연자는 공식 가이드대로 페이지를 열면 된다.
- 연결 판정은 HTTP 200이 아니라 앱의 SDK 콜백과 재조회값, Native 화면 표시로 한다.

## 4. 시연 전 준비 (시험 준비, 앱 기능 아님)

STEP 36에서 실제로 한 순서다.

1. P, 주행 제한 없음, 조수석 문 닫힘을 확인한다. Virtual Console 세션을 연다(3절).
2. 공조를 켠다. 하단 바의 공조 영역을 눌러 공조 패널을 열고, 바로 전원 버튼을 누른다.
   - 패널은 잠시 뒤 저절로 닫힌다. 닫힌 뒤에 누르면 아무것도 바뀌지 않는다(STEP 36 첫 탭). 그때는 패널을 다시 열고 곧바로 누른다.
   - 패널에서 Auto와 Sync가 꺼져 있는지 본다. 켜져 있으면 앱은 온도를 바꾸지 않는다(Sync).
3. 무드등을 켠다. 차량 설정 앱 [라이트]에서 아래로 내려 무드 조명 [켜기]를 누르고, [켜기]가 선택된 것을 확인한다.
   - 앱은 꺼진 무드등·공조를 켜지 않는다. 꺼져 있으면 그 항목은 조정하지 않는다.
   - 버튼을 눌렀다는 것만으로 켜졌다고 보지 않는다. 화면 표시와 Console 값으로 확인한다.
4. 시작 전 차량의 실제 초기값을 적어 둔다. STEP 36에서는 무드등 밝기 70·흰색, 풍량 3, 운전석·조수석 22.0이었다. 끝난 뒤 비교에 쓴다.
5. 앱 준비 화면에서 [무드등 조정]·[바람 줄이기]·[운전석 온도 맞추기]가 켜져 있는지 보고, 운전석 온도를 원래와 다른 값(STEP 36: [+] 1회로 22.5°C)으로 고른다. 온도는 차량이 알려 준 범위·간격 안에서만 고를 수 있다. 휴식 소리는 켬/조용히와 크기 중에서 고른다(STEP 36: 조용히).
6. 픽업 시각이 지났거나 쉴 시간이 3분보다 짧으면 [지금 기준으로 다시 설정]을 누른다. 누를 때만 지금 기준 새 시각(20분 뒤, 5분 단위 올림)으로 바뀐다. 앱이 스스로 바꾸거나 휴식을 시작하지 않는다.

## 5. 시연 흐름

### 5-1. 4항목 적용과 앱 이탈 복원 (STEP 36, 0.2.2)

1. 준비 화면에서 [쉬기 시작]을 누른다. 무드등 밝기가 낮아지고(70→30) 따뜻한 색으로 바뀌며, 풍량이 한 단계 줄고(3→2), 운전석 온도가 고른 값(22.0→22.5)이 된다. 조수석 온도는 그대로다.
2. 10초 동안 누르지 않으면 화면이 어두워진다(STEP 36에서 확인). 어두운 화면의 첫 터치는 깨우기만 한다([휴식 끝내기] 자리를 눌러도 끝나지 않는다. STEP 19, 0.2.0에서 확인).
3. 하단 바의 내비게이션 아이콘을 눌러 실제 다른 앱으로 전환한다. 휴식은 앱 이탈(APP_LEFT)로 끝나고, 종료 안내음·음성은 나오지 않는다. 앱 화면이 가려진 동안에도 4항목이 원래 값으로 돌아간다.
4. 쉼표 캐빈으로 돌아오면 종료 화면에 "앱 화면을 벗어나 휴식을 멈췄어요"와 4항목·자동 모드의 "원래대로 돌렸어요"가 나온다. 남은 기록 카드는 없고, 휴식이 다시 시작되지 않는다.
5. [다시 쉬기]로 준비 화면에 돌아간다.

### 5-2. 4항목 적용 뒤 자연 시간 종료 (STEP 38, 0.2.2)

1. 4절 준비를 마친 뒤, 쉴 시간이 3분 이상인 가장 이른 픽업 시각을 고른다. STEP 38에서는 [지금 기준으로 다시 설정]으로 03:05를 받은 뒤 [−5분] 3회로 02:50(휴식 종료 02:48, 약 5분 43초)을 골랐다.
2. [쉬기 시작]을 누른다. 4항목이 5-1의 1과 같이 바뀐다(무드등 70→30·따뜻한 색, 풍량 3→2, 운전석 22.0→22.5, 조수석 그대로).
3. 10초 뒤 화면이 어두워진다. 종료 시각까지 쉼표 캐빈을 앞에 둔 채 누르거나 다른 앱으로 가지 않는다. 조수석 문 닫힘과 P를 유지한다.
4. 종료 시각에 휴식 소리가 멈추고 시간 종료로 끝난다. 안내음이 나오고 4항목이 원래 값(70·흰색, 3, 22.0)으로 돌아간 뒤(STEP 38: 종료 뒤 약 1.5초), 기기 안 음성 "픽업 2분 전이에요"가 나온다.
5. 종료 화면에 "정한 휴식 시간이 끝났어요. 픽업 2분 전이에요.", "안내음과 음성으로 알렸어요", 4항목·자동 모드의 "원래대로 돌렸어요"가 나온다. 남은 기록 카드는 없다.
6. [다시 쉬기]를 누르면 아직 지나지 않은 픽업 시각이 남아 시작할 수 없다는 안내가 나온다. 이어서 쉬려면 [지금 기준으로 다시 설정]을 누른다. 휴식이 저절로 시작되지는 않는다.

- 휴식 소리를 켬으로 고르면 끝나기 60초 전부터 소리가 작아진다(시작 때 설정한 VolumeShaper). STEP 38은 조용히로 시험했고, 실제 스피커로 듣지는 않았다.
- 이전 시험(STEP 35, 같은 APK): 무드등·공조가 꺼져 있어 차량 값을 바꾸지 않은 상태로 자연 시간 종료와 종료 직후 [다시 쉬기]를 확인했다(약 4분 휴식).

- 시간: 쉴 시간은 3분 이상이어야 시작할 수 있고, 픽업 시각은 ±5분 단위로만 고른다. 그래서 자연 종료까지 보통 3~8분이 걸린다. 데모 모드·시계 조작·가짜 값·자동 시작은 없다.
- 짧게 보여 줄 때는 [휴식 끝내기] 또는 다른 앱 전환(앱 이탈)으로 끝낼 수 있다. 두 경우 모두 바꾼 값을 원래대로 돌린다. [휴식 끝내기]는 0.2.2로 다시 시험하지 않았다(STEP 8·9 이전 빌드에서 확인).

### 5-3. 시연 뒤 정리 (STEP 36·38에서 한 순서)

1. 앱 준비 화면에서 운전석 온도를 원래 고른 값(22.0°C)으로 되돌린다.
2. 차량 설정 앱 [라이트]에서 무드 조명을 처음 상태([끄기])로 되돌린다.
3. 공조 패널을 열고 바로 전원 버튼을 눌러 처음 상태(OFF)로 되돌린다.
4. 4절에서 적은 초기값과 지금 값을 비교한 뒤 Console 페이지를 닫는다.

### 5-4. 지난 빌드 기록 (STEP 19, 0.2.0)

- 자연 시간 종료: 무드등이 꺼져 있어 공조 2항목만 바뀌고 돌아왔다.
- 앱 이탈: 차량 설정 앱으로 전환했다. 무드등·공조 4항목이 바뀌었다가 돌아왔다.
- 첫 시간 종료 시도는 문 신호 공백으로 안전 중단돼 실패로 남겼다.

## 6. 문제가 생겼을 때

- Console 연결이 끊기면 차량 값 반영이 실패할 수 있다. 앱은 Console을 직접 감시하지 않는다.
- 앱은 조수석 문 상태 미확인, P 상실처럼 관측한 안전 조건을 잃으면 휴식을 멈춘다.
  - 바꾼 값은 쓰기 조건(P 등)이 맞을 때만 돌린다. 조건을 잃었으면 복원을 보류하고 기록을 남긴다.
- 기록이 남으면 다음 화면의 남은 기록 카드에서 [원래대로]로 정리한다.
  - 응답을 받지 못한 요청의 기록은 지우지 않는다(앱도 막는다). 차량에서 직접 맞춘다.
  - [기록 지우기]는 기록만 지우고 차량을 되돌리지 않는다.
- 강제 종료로 정리하지 않는다.
- 전제가 불안정했던 실행(예: STEP 19의 첫 시도)은 성공으로 보지 않는다.

## 7. 미완료와 검증 한계

- 시트 자동 조절: 미충족(F11). 공식 지원 포럼 문의 [#36](https://github.com/Pleos-Playground/pleos-playground-api/discussions/36)는 진행 중이다(PM 관리). 해결 계획은 직접 원인 분리와 대안 검증이다.
- 실제 스피커로 듣는 확인은 하지 않았다(`-no-audio`). 재생·포커스·음성 콜백은 로그로 확인했다. 이 단계의 완료 조건은 아니다.
- 실제 차량, 시동 꺼짐, Suspend에서의 동작은 확인하지 않았다.
- 에뮬레이터 cold start 첫 프레임 끊김과 문 상태 일시 오류(약 1초 뒤 회복)가 관측됐다. 해결됐다고 보지 않는다([verification/sdk-dispatch.md](verification/sdk-dispatch.md)).
