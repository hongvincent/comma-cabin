# 실제 사용 화면 정리와 실행 산출물 점검 (STEP 10)

- 날짜: 2026-11-13
- 목적: 준비 화면에서 [쉬기 시작]을 찾느라 스크롤하던 문제를 없앤다. 구현된 무드등·바람·운전석 온도·소리·종료 안내가 한 앱으로 보이게 정리하고, release 빌드를 점검한다.
- 바꾸지 않은 것: 차량·오디오 제어 controller, 포트, 기록 형식·코덱, 세션 시간·시작·종료 계약. controller에서는 화면에 보이는 문자열만 바꿨다(아래 1절).
- 판정 기준: 차량 값은 SDK 재조회값으로 판정한다. Virtual Console은 보조 증거다.

## 1. 바꾼 것

| 항목 | 내용 |
| --- | --- |
| 화면 구조(`RestScreen.kt`) | 모든 화면을 "스크롤되는 내용 + 하단 고정 버튼 영역"으로 나눴다. 고정 버튼은 [확인했어요]·[쉬기 시작]·[휴식 끝내기]·[다시 쉬기]다. [쉬기 시작]은 기존 `canStart`를 그대로 쓰고, 막혀 있으면 첫 이유를 바로 위에 보여 준다. 화면이 바뀌면 스크롤 위치를 새로 시작한다. 어두운 휴식 화면에는 조작을 하나도 두지 않는다(첫 터치는 깨우기만) |
| 넓은 화면 | 폭 1000dp 이상이면 준비·종료 화면을 2열로 배치한다. 준비 화면 왼쪽은 픽업·종료 시각, 시작 조건, 남은 기록 카드이고, 오른쪽은 소리·무드등·공조 설정과 시트 안내다. 좁으면 1열로 스크롤한다 |
| 개발 진단 | debug 빌드에서만 보인다. 하단 버튼과 겹치지 않도록 제목 줄 오른쪽으로 옮겼다 |
| 시트 | 준비 화면 카드와 첫 실행 안내에 "시트 자동 조절은 아직 지원하지 않아요. 차량에서 직접 편한 자세를 맞춰 주세요"만 보여 준다. 토글이나 시트 상태 표시는 없고, 시트를 움직이지 않는다 |
| 좌석 이름(`SeatNames.kt`) | 같은 항목의 영역이 여러 개면 쉬운 좌석 이름으로 구분한다: 운전석, 조수석, 앞좌석, 뒷좌석, 앞·뒤 좌석(전체라고 부르지 않음). SDK 키는 화면에 보이지 않는다 |
| 첫 실행 안내 v5 | 같은 사실(차량 설정 변경과 복원, 직접 바꾼 값 보존, 꺼진 무드등·공조는 켜지 않음, Sync 켜짐이면 온도 미적용, 문 열림·P 상실·앱 이탈 때 중단, 깨우기 보장 없음)을 짧게 쓰고 시트 문장을 더했다. 기존 설정은 그대로 둔다 |
| 앱 이름·아이콘 | 이름은 `쉼표 캐빈`(`@string/app_name`)이다. 아이콘은 직접 그린 쉼표 벡터 적응형 아이콘(배경 `#0B0F14`, 쉼표 `#7FCFC4`, monochrome 포함)이다. 외부 이미지는 쓰지 않았다 |
| 오류 표시(`RestClimate`·`RestLighting`의 표시 문자열만) | 화면에는 한국어 이유만 보여 준다(예: "현재 값을 읽지 못해 되돌리지 않았어요"). SDK 예외·시간 초과 같은 기술 내용은 로그에만 남긴다(`… — 원인: …`). 상태 전이·쓰기·잠금·기록은 그대로다 |
| 남은 기록 문구 | "아직 휴식 값이에요"(공조)와 "아직 휴식 값으로 바뀌어 있어요"(무드등)를 "휴식 중 적용한 기록이 남아 있어요. 지금 설정은 확인이 필요해요"로 바꿨다. 현재값을 읽지 않았는데 차량이 휴식 값이라고 단정하지 않기 위해서다 |

## 4. 실기 중 환경 사고

- #7의 강제 종료 무렵 에뮬레이터 부하가 매우 높았다(load average 32).
- 차량 HAL 프로세스(`sdv_vhal_rust`)의 PID가 209 → 6811 → 9451 → 11576으로 바뀌었고 "VHAL has died"가 기록됐다. `com.android.car`와 SystemUI 등도 다시 시작됐다.
- 첫 신호는 우리 앱 강제 종료(`1794501763.867`)보다 앞선 `1794501759.149`의 carwatchdog 심박 시간 초과였다. 원인은 확인하지 못했다.
- 그 뒤 SDK 값(전원 false, 풍량 3, 온도 20.0·조회 불가)과 Console(전원 true, 풍량 2, 22.5/22.0)이 서로 달랐다. 판정은 SDK 값으로 했고, 정상 차량 패널로 전원·온도를 다시 만들어 #8을 진행했다.
- 앱은 이 동안 공조 쓰기를 하지 않았다. 기록 파일도 고치거나 지우지 않았고, 시스템 서비스를 건드리지 않았다.

## 5. release 점검

**정적 확인**(`build/release-static.txt`):
- debug와 release의 merged manifest 권한 11개가 같다. INTERNET·마이크·위치·카메라는 없다.
- `allowBackup=false`이고, release는 debuggable이 아니다(`pkgFlags=[HAS_CODE ALLOW_CLEAR_USER_DATA]`).
- label은 `쉼표 캐빈`이고 아이콘 리소스가 있다.

**QA 서명**: `app-release-unsigned.apk`를 기존 기본 개발용 debug keystore(`androiddebugkey`)로 서명해 `app/build/reports/product-ui/app-release-qa.apk`를 만들었다.
- 인증서 SHA-256 `e2662cec…`는 debug APK와 같다.
- 이 서명은 내부 QA용이며 배포·출시용 서명이 아니다. 새 키를 만들거나 키를 복사·출력하지 않았다.

**실제 실행**: 같은 user 10에 덮어 설치했다. 기존 설정이 유지돼 안내가 다시 나오지 않았다.
- 준비 화면에 [개발 진단]이 없었다(0개).
- 시작 → 어두움 → 깨우기 → [휴식 끝내기] `USER` 종료 → [다시 쉬기]가 동작했다(공조 전원 OFF·무드등 OFF라 차량 쓰기 0).
- 앱 서랍과 하단 바에 쉼표 아이콘과 "쉼표 캐빈"이 보였다(r01~r04).
- 그 뒤 최종 debug APK로 다시 설치했다.

## 6. 최종 상태(최종 debug APK, SDK 재조회)

- 차량: P, 문 닫힘.
- 공조: 전원 false(차량 패널로 끔)·Auto false·Dual false, 풍량 3, 22.0/22.0.
- 무드등: 스위치 OFF, 밝기 70, 색 `0x00FFFFFF`.
- 등받이: 0.
- Console 값도 같다(Console 앰비언트 `mode`는 On으로 보임).
- 기록 파일: 공조 `{"groups":[]}`, 무드등·제어 `{"records":[]}`, 밝기 v1 파일 없음. 오디오 포커스 보유자 없음.
- 설정: `onboarding_version=5`, `rest_sound=QUIET`, `rest_level=LOW`, `rest_lighting`·`rest_fan`·`rest_temp`=true, `rest_temp_c=22.0`.

## 7. 실행하지 않은 것과 한계

- 남은 기록 문구 변경(U-5)은 소스·빌드로만 확인했다. 기록이 남은 화면을 이 APK로 다시 띄우지는 않았다.
- 실제 SDK 오류 표시 분리는 #8에서 온도 `PropertyNotAvailable` 한 경우만 실기로 봤다. 다른 경로는 단위 테스트와 소스로 확인했다.
- 다음 실행에서 남은 기록의 현재값을 쓰기 없이 먼저 읽어 보여 주는 동작(제품 요구사항 6-1·6-6)은 아직 없다(후속).
- 좁은 화면(1열)은 폭 조건으로 코드만 있고, 실기에서는 보지 못했다. 이 기기의 앱 영역은 넓다.
- 화면 꺼짐만 시험했다. 시동 꺼짐·Suspend, 실차, 실제 스피커 청취는 확인하지 않았다.
- 일부 실기 조작 기록에 "개발 진단 not found"가 있다. 화면을 아래로 스크롤해 제목 줄이 가려진 경우였고, 다시 위로 스크롤해서 눌렀다.
