# 쉼표 캐빈

차 안에 머무는 짧은 시간, 빛과 소리로 나만의 휴식 공간을 만드는 차량용 앱

퇴근길에 잠시 차를 세웠을 때, 충전을 기다릴 때, 누군가를 데리러 조금 일찍 도착했을 때. 쉼표 캐빈은 운전자가 차 안에서 휴식을 시작하고, 편안한 소리를 들으며 다음 일정을 준비하도록 돕는다. 주차한 차량의 인포테인먼트 화면과 스피커, 차량 상태를 함께 활용한다.

## 장면과 사용 경험

| 머무는 순간 | 사용자가 원하는 것 | 경험 구상 |
| --- | --- | --- |
| 퇴근 후 잠깐 주차 | 집에 들어가기 전 혼자 쉬기 | 주차 상태를 확인하고 빗소리와 차분한 화면을 켠다. |
| 충전 대기 | 충전하는 동안 조용히 머무르기 | 남은 충전 시간을 확인하며 쉬는 경험을 검토한다. 충전 정보 연동은 후속 과제다. |
| 픽업 대기 | 기다리는 동안 쉬면서 상대를 맞을 준비 | 직접 입력한 픽업 시각 2분 전이나 조수석 문이 열릴 때 휴식을 끝낸다. |
| 다음 일정 전 잠시 정차 | 짧은 빈 시간을 활용하기 | 사용자가 끝낼 시점을 정하고 편하게 쉴 수 있는 방식을 검토한다. |

## 지금 확인할 수 있는 경험

v0.2.0에서 운전자는 P 기어, 차량 화면 사용 허용, 조수석 문 닫힘을 확인한 후 픽업 시각을 입력하고 **휴식 시작**을 누른다. 앱은 앞유리에 떨어지는 빗소리를 재생하며, 차량의 Light SDK 값을 읽어 앱 화면 밝기에 반영한다. 값을 읽을 수 없을 때는 시스템 밝기를 사용한다. 화면에는 픽업 시각과 휴식 종료 시각이 함께 보인다.

픽업을 **19:30**으로 설정하면 **19:28**에 빗소리가 멈추고 ‘픽업 준비할 시간이에요’가 표시된다. 조수석 문이 먼저 열리면 빗소리가 바로 멈추고 ‘조수석 문이 열렸어요’가 표시된다. P 기어를 벗어나거나 필요한 신호를 잃는 등 안전 조건이 깨져도 재생을 중단한다. 두 종료 경로는 Pleos Connect 에뮬레이터에서 각각 확인했다. [에뮬레이터 검증 기록](https://github.com/hongvincent/comma-cabin/blob/db43cda49314145b5b7c829802856d3a824cf994/docs/verification.md)

## 발전시킬 빛과 소리

차량 실내의 기존 조명과 어울리는 화면 톤, 빗소리 외의 소리 선택, 사용자가 고르는 휴식 길이를 살펴본다. 충전 대기와 일정 전 휴식도 같은 경험으로 연결할 수 있는지 검토한다. 차량 무드램프의 밝기·색상 제어와 서라운드 채널 출력은 지원 차종과 SDK 권한·제공 범위, 실차 동작을 확인한 뒤 구현 가능성을 판단할 후속 아이디어다. 현재 MVP는 물리 조명이나 서라운드 채널을 제어하지 않는다.

## MVP 기반 숏폼 방향

차를 세운 저녁, 차 안의 은은한 조명과 빗방울을 보여 주며 시작한다. 인포테인먼트에서 휴식을 시작하면 빗소리가 흐르고 화면에 19:30 픽업과 19:28 종료가 보인다. 빛과 소리를 느낄 시간을 둔 뒤 예정 시각에 빗소리가 멈추는 장면을 보여 준다. 이어 다른 날을 배경으로 조수석 문이 먼저 열렸을 때 앱이 바로 멈추는 장면을 보여 준다. 각 컷의 짧은 하단 자막이 상황을 연결하고, 끝에는 쉼표 캐빈 아이콘을 둔다. 영상의 실내 조명은 휴식 공간의 분위기이며, 앱의 물리 조명 제어로 소개하지 않는다.

## 확인할 가설

- 주차 중인 운전자는 차 안에서 짧게 쉬기 위해 잔잔한 소리와 눈부심이 적은 화면을 사용하고 싶어 할 것이다. 퇴근·충전·픽업 상황별로 짧은 인터뷰와 사용 관찰을 진행한다.
- 픽업 대기자는 종료 시각과 문 열림에 맞춰 재생이 멈추면 동승자를 맞기까지 추가 조작이 줄어들 것이다. 보호자 8명이 평소 방식과 앱을 번갈아 사용하며 정시 도착과 조기 도착 과제에서 조작 횟수와 이해도를 기록한다.
- 실제 차에서는 차종별 상태 신호, 차량 오디오와 조명 지원 여부, 문 신호부터 스피커 출력이 멈출 때까지의 시간을 측정한다. 에뮬레이터 결과와 실차 결과를 별도로 기록한다.
