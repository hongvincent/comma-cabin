# 쉼표 캐빈 PRD

쉼표 캐빈은 주차한 차를 잠깐 혼자 쉴 수 있는 공간으로 바꾸는 Pleos Connect 앱입니다. 픽업 시각 2분 전이나 조수석 문이 열릴 때 빗소리가 멈춰, 운전자는 재생 버튼을 찾지 않고 동승자를 맞을 수 있습니다.

2026년 11월 13일 Manyfast **쉼표 캐빈 | 현대차그룹 차량용 앱 공모전** PRD 본문과 실제 조명 제어 검증 결과를 반영한 문서입니다. Manyfast의 요구사항·기능·정책 항목에는 기존 조명 미구현 문구가 남아 있으며 플랜 제한으로 수정하지 못했습니다. 이 문서의 조명 제어 및 검증 내용이 최신 결과입니다.

## 문제와 제품 범위

픽업 장소에 일찍 도착한 운전자는 차 안에서 잠시 쉴 수 있습니다. 약속 시각을 확인해야 하고, 상대가 먼저 와 문을 열면 인사하기 전에 재생을 끄기도 합니다. 주 2회 이상 학원 픽업을 하며 주차장에서 혼자 5분 이상 기다리는 국내 Pleos 차량 운전자를 먼저 대상으로 잡았습니다. 반복 픽업에서는 같은 상황을 여러 번 관찰할 수 있습니다. 국내 Pleos 앱 마켓 적용 차종에는 더 뉴 그랜저와 디 올 뉴 아반떼가 있습니다. ## 사용 시나리오

19:20에 학원 주차장에 도착한 운전자가 P 기어에 놓고 **19:30 픽업**을 선택합니다. 화면에서 **19:28 휴식 종료**와 준비 시간 2분을 확인한 다음 `휴식 시작`을 누릅니다. 지원되는 조명 밝기가 있으면 현재 밝기를 읽고 네 단계로 낮춥니다. 문이 닫혀 있으면 19:28에 재생이 멈추고 `픽업 준비할 시간이에요`가 표시됩니다. 동승자가 먼저 도착해 오른쪽 앞문을 열면 그때 재생이 멈추고 `조수석 문이 열렸어요`가 표시됩니다.

## 요구사항과 기능

| 요구사항 | 기능 | 수용 기준 |
| --- | --- | --- |
| 주차 중 픽업 휴식 시작 | 픽업 시각 선택과 종료 시각 확인 | 19:30을 고르면 19:28 종료와 준비 여유 2분을 표시합니다. 종료까지 1분 미만이면 준비 안내를 표시합니다. |
| 주차 중 픽업 휴식 시작 | 차량 상태 확인 후 수동 시작 | P 기어, 주행 UX 허용, 오른쪽 앞문 닫힘, 종료까지 1분 이상을 모두 확인하고 운전자가 시작을 선택하면 빗소리를 재생합니다. 확인할 수 없는 조건이 하나라도 있으면 시작을 막습니다. |
| 주차 중 픽업 휴식 시작 | 앰비언트 조명 밝기 제어 | 지원 좌석 영역의 밝기를 읽고 네 단계로 낮춥니다. 종료 시 앱의 마지막 확인값이 유지되면 시작 전 밝기를 복원하고, 사용자가 변경한 밝기는 유지합니다. |
| 픽업 시각과 조수석 문에 맞춘 종료 | 픽업 2분 전 예정 종료 | 문이 닫힌 상태로 19:28에 도달하면 재생을 정지하고 `픽업 준비할 시간이에요`를 표시합니다. |
| 픽업 시각과 조수석 문에 맞춘 종료 | 오른쪽 앞문 열림 종료 | 재생 중 Vehicle SDK의 오른쪽 앞문 `OPEN` 콜백을 받으면 소리와 휴식 화면 연출을 종료하고 `조수석 문이 열렸어요`를 표시합니다. 오른쪽 앞문 상태를 사용하므로 좌석 점유 정보는 필요하지 않습니다. |
| 안전 조건 상실 시 정지 | 운전 전환·조건 상실 시 정지 | P 해제, 주행 UX 제한, 차량 신호 상실, 오디오 포커스 상실, 화면 이탈 또는 수동 종료 시 재생을 멈춥니다. |

### 공통 차량 안전 정책

- 시작 직전에 기어, 주행 UX, 오른쪽 앞문 상태와 남은 시간을 확인합니다. 필요한 차량 신호가 재생 중 사라지면 멈춥니다.
- 문을 다시 닫거나 P로 돌아와도 자동 재생하지 않습니다. 휴식하려면 조건을 다시 충족한 상태에서 운전자가 직접 시작해야 합니다.
- 에뮬레이터 첫 실행에서 문 상태가 `확인 중`이면 공식 Virtual Console에서 오른쪽 앞문을 한 번 열고 닫아 구독 콜백을 확인합니다.

### 상세 설계에서 남은 결정

Manyfast의 기능·스펙에 열린 질문으로 기록된 항목입니다. 이미 지난 픽업 시각의 선택 제한 방식, 앱 재실행 시 픽업 설정 유지 여부, 예정 종료와 문 열림이 겹칠 때의 안내 우선순위, 안전 조건 상실과 P→D 정지 화면에 이유를 표시하는 방식입니다.

Pleos Connect Emulator 2.1.0, AAOS API 34, 2560 × 1440, 160 dpi의 분할 화면에서 서명된 v0.2.0 APK를 설치해 확인했습니다. 각 행은 독립된 시험입니다. [검증 기록과 재현 방법](https://github.com/hongvincent/comma-cabin/blob/db43cda49314145b5b7c829802856d3a824cf994/docs/verification.md)

| 스펙 | 트리거 | 에뮬레이터 관측 |
| --- | --- | --- |
| 19:30 픽업의 19:28 예정 종료 | 조수석 문이 닫힌 상태에서 예정 종료 시각 도달 | **19:28:00.052** 종료 판단. 재생이 정지하고 `픽업 준비할 시간이에요`를 표시했습니다. |
| 오른쪽 앞문 열림 종료 | 공식 Virtual Console에서 오른쪽 앞문을 `OPEN`으로 바꿔 콜백 수신 | **19:26:54.874** 문 열림 신호와 종료 판단. 재생이 정지하고 `조수석 문이 열렸어요`를 표시했습니다. 문을 다시 닫아도 자동 재생되지 않았습니다. |
| P에서 D 전환 시 재생 정지 | 빗소리 재생 중 P에서 D로 전환 | **19:26:47.375** 종료 판단. 재생이 정지했고 P에 복귀해도 자동 재생되지 않았습니다. |

문 열림 이벤트부터 로그에 `isPlaying=false`가 기록될 때까지 **45ms**였습니다. 실차의 스피커 출력 지연은 후속 검증 대상입니다. 주행 UX 제한, 차량 신호 상실, 오디오 포커스 상실, 화면 이탈 대응은 구현 범위에 있으며 각각의 에뮬레이터 실측 기록은 확보 전입니다.

## 조명 제어 APK의 에뮬레이터 검증

Pleos Connect Emulator 2.1.0과 Vehicle SDK 2.3.2에서 `CAR_LIGHTS`, `CONTROL_CAR_LIGHTS` 권한과 capability를 확인하고 실제 앱의 휴식 시작·종료를 검증했습니다. 앱은 조명 값 읽기·쓰기 지원 영역을 확인한 후 밝기를 네 단계로 낮추고 각 단계의 반영을 재조회합니다. 읽기·쓰기나 권한이 지원되지 않거나 확인되지 않으면 빗소리 휴식은 계속하고 실패를 로그에 남깁니다.

| 독립 시험 | 에뮬레이터에서 확인한 값 |
| --- | --- |
| 휴식 시작, 초기 밝기 80 | 80 → 70 → 60 → 50 → 40 |
| 조수석 문 열림 | 재생이 멈추고 밝기 40 → 80 복원 |
| 19:30 픽업의 19:28 예정 종료 | 재생이 멈추고 밝기 40 → 80 복원. 시험을 위해 에뮬레이터 시간을 19:27:58로 설정했습니다. |
| 사용자 변경 | 휴식 중 65로 변경한 뒤 문을 열어도 65 유지 |
| P에서 D로 전환 | 재생 정지 및 80 복원. P로 돌아와도 자동 재생하지 않음 |

이 값은 Virtual Console과 SDK 재조회에서 확인한 차량 상태이며 실차 LED 광량 측정값이 아닙니다. 영상의 연속 조명 변화는 이미지 연출이고 실제 APK는 지원된 한 영역을 네 단계로 제어합니다. SDK의 매우 늦은 쓰기, 프로세스 강제 종료 또는 사용자의 동시 조작과 이미 전송된 요청이 겹치면 원래 값 복구가 보장되지 않습니다. 제어 권한의 배포 승인, 차종별 지원, 실차의 광량·색상·스피커 지연을 후속 검증합니다. [Pleos Vehicle SDK](https://document.pleos.ai/en/docs/pleos-only/connect-sdk-pleos/Vehicle/intro) · [Pleos 권한 안내](https://document.pleos.ai/en/docs/pleos-only/connect-sdk-pleos/Vehicle/vehicle-permission)

## 사용자 검증 계획과 기준

같은 보호자 8명이 평소 방식과 쉼표 캐빈으로 **정시 도착**과 **조기 도착** 과제를 수행합니다. 참가자마다 조건의 순서를 바꿔 진행하고, 과제별로 동승자에게 인사하기까지 추가 조작 횟수를 셉니다. 아래 수치는 파일럿 진행 기준과 가설입니다.

| 항목 | 기준 |
| --- | --- |
| 종료 규칙 이해 | 도움 없이 설명한 사람이 8명 중 6명 이상 |
| 다음 과제에서의 선택 | 쉼표 캐빈을 선택한 사람이 8명 중 5명 이상 |
| 후속 파일럿 | 두 기준을 충족하면 20명으로 4주간 진행 |
| 4주차 재이용 | 첫 휴식 완료자 중 4주차에 다시 휴식을 완료한 비율 50% 목표. 4주차에 픽업 대기가 있었던 참가자 수도 함께 기록 |
| 초기 월간 활성 사용자 가설 | 보호자 커뮤니티의 월 적격 도달 200명 × 설치율 20% × 설치자 중 월 1회 이상 휴식 완료율 50% = 20명 |

실차 측정과 고객 조사를 진행해 위 가설을 확인할 계획입니다.
